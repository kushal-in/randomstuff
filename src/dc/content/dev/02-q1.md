Take a look at the snippet below. It compiles cleanly with zero warnings on
`g++ -Wall -Wextra -std=c++17`.

```cpp
#include <iostream>
#include <vector>
#include <string>

std::string* get_label(std::vector<std::string>& cache, size_t index) {
    if (index >= cache.size()) return nullptr;
    return &cache[index];
}

int main() {
    std::vector<std::string> tags = {"dev", "cp", "core"};

    // 1. Grab a direct pointer to the second element
    std::string* ptr = get_label(tags, 1);

    // 2. Grab a reference to the first element
    const std::string& ref = tags[0];

    // 3. Mutate the container
    for (int i = 0; i < 50; ++i) {
        tags.push_back("extra_" + std::to_string(i));
    }

    // 4. Access
    std::cout << "Tag via pointer: " << *ptr << '\n';
    std::cout << "Tag via ref:     " << ref  << '\n';

    return 0;
}
```
1. What happens during runtime at step 4? Will it output the original values, crash, or do something else? Explain the underlying mechanism in memory.

2. Would replacing `*ptr` and `ref` with `std::string_view` fix the issue? Why or why not?

3. How would you refactor `main()` to safely read elements while allowing the vector to grow?
